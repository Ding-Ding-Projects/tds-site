# Data pipeline

The 2026-09-26 snapshot contains 2,649 non-redirect pages from namespace 0 and 186 entries from namespace 2900, for 2,835 source records. The wiki header and API title inventory reported different totals on the same date, so the exact paginated API inventory is recorded rather than replaced by a guessed fixed total.

## Live inventory recheck

On 2026-09-26, the public `action=query&list=allpages` inventory was paginated again for namespaces 0 and 2900 with redirects excluded. It returned 2,649 and 186 entries respectively. Comparing the live page IDs with the checked-in `public/wiki/index.json` found no additions or removals in either namespace. A page read showed 2,638 articles, while a subsequent `action=query&meta=siteinfo&siprop=statistics` request reported 2,639 articles. [MediaWiki documents the siteinfo `articles` field as a content-page statistic](https://www.mediawiki.org/wiki/API:Siteinfo/en), while `allpages` enumerates pages, so the values are not interchangeable. The project uses the exact eligible page-ID inventory for corpus completeness and records both summary values without claiming their precise reconciliation.

Each content record retains its namespace, page ID, title, current revision ID, source timestamp, source URL, history URL, retrieval snapshot date, and the wiki copyright-policy link. The complete imported revision source is available in an expandable section and full text is indexed for search. For namespace 0 entries, the article view requests the HTML for that exact imported page revision through the MediaWiki REST revision endpoint. The Worker sanitizes that HTML into a bounded semantic format, maps links for pages in the imported corpus into the guide, and drops scripts, styles, hidden challenge markup, and remote image files. Image alternative text remains readable, and file-description links remain source links. The 186 namespace 2900 map entries use the local imported-source formatter because the REST endpoint returns a map-widget fragment without a page-revision envelope, not a complete readable article. A 20-second timeout and 6 MB response cap keep the endpoint bounded. If rendered content is unavailable, the readable partial Wikitext view and the complete imported source remain available. The page revision is pinned, but this does not archive the historical revisions of templates it transcludes. Redirects remain aliases to canonical guide entries. Talk, user/profile, discussion, deleted, and revision-history archives are outside this guide's corpus.

The current wiki policy says mixed current pages may be reused as adaptations under CC BY-SA 4.0 International when attributed and marked as changed; unchanged pre-2026-09-12 wording remains CC BY-SA 3.0. Every imported record shows the current-page adaptation notice, page link, history link, and policy link. Media files remain excluded unless individually verified.

`scripts/import-wiki.mjs` uses a descriptive user agent, namespace continuation, 50-page revision batches, and a short inter-request delay. `npm run audit:wiki-inventory` performs a read-only, paginated page-ID comparison for namespaces 0 and 2900; it fails with exact additions, removals, renames, namespace moves, or duplicate IDs. Its comparator has fixture coverage for unchanged and drifted inventories. `scripts/extract-tower-stats.mjs` structures 83 tower infobox pages and upgrade levels from the same dated snapshot, retaining damage method and finite regular placement limits where available. The tower-stat contract cross-checks the rows against the source snapshot and refuses generic DPS for special damage methods. `scripts/materialize-wiki.mjs` produces one lazy-loaded file per article, a title index, and a full-text inverted search index. The source markup is displayed as escaped text, so imported markup cannot execute. Automated resumable corpus refresh remains open work.

The MediaWiki API's `action=parse` route returned a Cloudflare challenge to the current Node fetch context on 2026-09-26. The supported REST revision HTML route now provides source-rendered page content for the captured revision without requiring a browser cross-origin request. It is still an online rendering service, not a locally archived rendered copy: offline use relies on the imported wikitext fallback, and transcluded template content may not reflect its historical version. The sanitizer supports semantic article structures and strips active content and media. `npm run test:wiki` covers sanitizer behavior, safe links, current-corpus completeness, deliberate missing-entry/provenance cases, and the audit-to-snapshot hash. The full 2026-09-26 audit sanitized all 2,649 namespace 0 revisions; 186 map entries are routed to the full-source fallback. The local production Worker returned 200 for a standard imported revision, 501 with the map fallback marker, and 404 for an out-of-snapshot ID. Run `npm run audit:wiki-rendered` to recheck the strategies against a refreshed snapshot. Cross-viewport visual verification of the new article surface remains open.
