## Live inventory recheck

On 2026-09-26, the first paginated public `action=query&list=allpages` inventory for namespaces 0 and 2900 returned 2,649 and 186 entries. A later full refresh found one new namespace 2900 page; the current live inventory now matches 2,649 and 187 entries with no additions, removals, renames, or namespace moves against the refreshed snapshot. A page read showed 2,638 articles, while a subsequent `action=query&meta=siteinfo&siprop=statistics` request reported 2,639 articles. [MediaWiki documents the siteinfo `articles` field as a content-page statistic](https://www.mediawiki.org/wiki/API:Siteinfo/en), while `allpages` enumerates pages, so the values are not interchangeable. The project uses the exact eligible page-ID inventory for corpus completeness and records both summary values without claiming their precise reconciliation.

Each content record retains its namespace, page ID, title, source revision ID and timestamp, page URL, history URL, retrieval timestamp, direct CC BY-SA 4.0 and historical CC BY-SA 3.0 links, copyright-policy URL, attribution statement, and structured adaptation provenance. The provenance records which display route applies, which transformations are made, that source markup is preserved, and the historical-license notice. The article view shows both license links and the policy page, while the complete imported revision source is available in an expandable section and full text is indexed for search. Every standard namespace 0 page has a checked-in, revision-bound sanitized semantic render in `public/wiki/rendered/`; the article reader loads that same-origin cache first, so full readable article structure is available without requesting the source wiki. The bounded MediaWiki REST route remains a fallback for a missing cache file. The sanitizer maps indexed source pages into the guide, drops scripts, styles, hidden challenge markup, and remote image files, converts image alternatives to text, and retains safe page links. The 187 namespace 2900 map entries use the local imported-source formatter because the REST endpoint returns a map-widget fragment without a page-revision envelope, not a complete readable article. A 20-second timeout and 6 MB response cap keep the fallback endpoint bounded. If both rendered paths are unavailable, the readable partial Wikitext view and complete imported source remain available. The page revision is pinned, but this does not archive the historical revisions of templates it transcludes. Redirects remain aliases to canonical guide entries. Talk, user/profile, discussion, deleted, and revision-history archives are outside this guide's corpus.

The current wiki policy says mixed current pages may be reused as adaptations under CC BY-SA 4.0 International when attributed and marked as changed; unchanged pre-2026-09-12 wording remains CC BY-SA 3.0. Every imported record shows the current-page adaptation notice, page link, history link, and policy link. Media files remain excluded unless individually verified.

`scripts/import-wiki.mjs` uses a descriptive user agent, namespace continuation, 50-page revision batches, and a short inter-request delay. `npm run audit:wiki-inventory` performs a read-only, paginated page-ID comparison for namespaces 0 and 2900; it fails with exact additions, removals, renames, namespace moves, or duplicate IDs. `npm run audit:wiki-revisions` separately checks all captured page IDs against their current revision IDs, writes a dated `data/wiki-revision-audit.json` report, and flags stale, missing, newly eligible, or duplicate records. Both comparators have fixture coverage for unchanged and drifted inventories. `scripts/extract-tower-stats.mjs` structures 83 tower infobox pages and upgrade levels from the same snapshot, retaining damage method and finite regular placement limits where available. The tower-stat contract cross-checks the rows against the source snapshot and refuses generic DPS for special damage methods. `scripts/materialize-wiki.mjs` produces one lazy-loaded file per article, a title index, and a full-text inverted search index. The source markup is displayed as escaped text, so imported markup cannot execute. The full refresh is repeatable; automated resumable partial refresh remains open work.

The MediaWiki API's `action=parse` route returned a Cloudflare challenge to the current Node fetch context on 2026-09-26. The supported REST revision HTML route provides source-rendered page content for the captured revision without requiring a browser cross-origin request. The 2026-09-26 audit sanitized all 2,649 current namespace 0 revisions with 0 unavailable responses and materialized 2,649 local render files totaling 299,462,947 bytes. The manifest binds each file hash and page revision to canonical page-ID and revision tuples from `data/wiki-revisions.json`; `.gitattributes` keeps render-cache bytes on LF across checkouts. The audit reuses an existing cache entry only after checking its revision, content identity, size, and SHA-256; a negative completeness check rejects missing, stale, altered, duplicate, and orphan cache records. The 187 map entries use the full-source fallback. Historical transcluded templates are not archived. The sanitizer supports semantic article structures and strips active content and media. `npm run test:wiki` covers sanitizer behavior, safe links, corpus completeness, missing-entry and provenance negatives, and the line-ending-independent revision/cache hashes. The local production Worker previously returned 200 for a standard imported revision, 501 with the map fallback marker, and 404 for an out-of-snapshot ID. Cross-viewport visual verification of the article surface remains open.
