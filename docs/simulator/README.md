# Tower simulator

Source values and derived values are stored separately. Keep unlock cost distinct from in-match placement and upgrade costs. Record units and source-specific exceptions for burst, charge, cooldown, rev-up, abilities, buffs, targeting, defense, splash, mode variants, player count, and rounding.

The current extractor processes all 83 source pages with a `TowerInfobox` and reads regular upgrade rows from the same dated revision snapshot. Each record retains its damage method, regular-mode placement limit where the source provides one, and source revision provenance. The placement-count slider respects finite caps and uses an explicit 1-10 estimate when the source gives no finite cap. Each level uses the extracted regular damage, interval, range, and detection values. Detection footnotes remain separate from the Hidden, Lead, and Flying state labels. Investment reports both per-tower and selected-count totals from the placement and upgrade costs. Missing placement costs display as unknown.

The simulator can optionally compare two towers at independently selected upgrade levels. It shows each supported source-aware rate, selected-count estimate, investment, range, placement cap, and detection flags side by side. Count totals respect each tower's placement limit. The searchable tower index uses the same source-aware formula function as the calculator; unsupported cycles display `Not modeled` instead of a generic single-hit estimate. The comparison interaction has not yet received a fresh built-site capture.

For a simple single-hit tower, the displayed steady-rate estimate is damage divided by the attack interval in seconds. It is not a guaranteed in-match damage rate and excludes buffs, target downtime, overkill, enemy defense, and range uptime. Where the source also describes firing startup, such as Minigunner rev-up, the UI says that startup is omitted. Accelerator uses the source-listed cycle formula `Overcharge / (Charge-Up + Cooldown + (Overcharge / Damage × Tick))`, with each input extracted from its imported regular-mode statistics table. The calculator displays those cycle inputs and labels its fire interval as a damage tick. The formula matches the page's published DPS values at Levels 0 and 5. Operator uses `(Damage × Burst Count) / (Burst Cooldown + (Firerate × Burst Count))` for Levels 0–4, then switches to `Damage / Firerate` for the single-fire Levels 5–6. Coordination damage buffs remain excluded. Soldier uses `(Damage × Burst Count) / (Cooldown + (Firerate × Burst Count))`, where Firerate applies between shots in one burst. Its Level 0 estimate is 2.93 and Level 4 is 54.55. Golden Soldier uses the same burst formula at Levels 0–2, then switches to `Damage / Firerate` at Levels 3–4. Its Level 0 estimate is 3.81 and Level 4 is 100. Freezer uses `(Damage × Burst Count) / (Cooldown + (Firerate × Burst Count))`; its first three levels have one shot and no between-burst cooldown, and Levels 3–4 use six and eight shots respectively. Freezer's chill and slowdown effects are excluded from the direct damage estimate. Commando uses `(Ammo × Damage) / (Ammo × Firerate + Reload Time)` for the gun magazine cycle. For example, Level 0 is `(30 × 5) / (30 × 0.225 + 2.25) = 16.67`; Level 4 is `(80 × 23) / (80 × 0.1 + 1.25) = 198.92`. Its missile ability damage is excluded even though the source lists combined gun-and-missile DPS separately. Demoman, Golden Demoman, and Paintballer use the source-listed `Splash Damage / Firerate` as a per-target-equivalent rate. Paintballer's source-listed maximum-hit value of 8 is displayed separately; the calculator does not assume all possible hits land. Ranger uses `(Damage / Firerate) + (Splash Damage / Firerate)` for the direct hit and Level 4 splash. Its source-listed maximum of three splash hits is displayed separately and is not multiplied into the one-target rate. Mortar uses the same source formula with splash and firing-rate values selected by their named table columns; its estimate assumes full inner-sphere splash and excludes cluster-bomb damage, target count, and projectile travel time. Rocketeer uses `(Splash Damage × Missile Count) / Firerate` from its regular statistics table. Its UI shows the extracted missile count, but the estimate follows the source's one-target assumption and excludes projectile travel time. These splash estimates are not total output: the simulator does not model how many enemies a blast hits, blast overlap, or all map geometry. These formulas and inputs come from the dated imported source snapshot. Other special methods, including Biologist's mixed plant attacks and Pulse Trooper's sweeping pulse, remain unmodeled until a complete cycle formula is source-verified. ## Toxic Gunner burst and poison estimate

The current [Toxic Gunner page](https://tds.wiki/w/Toxic_Gunner) publishes separate gun and poison formulas, then adds them for its displayed DPS. For Levels 0–3, the simulator calculates `(Damage × Burst Count) / (Cooldown + (Firerate × Burst Count)) + (Poison Damage / Tick)`. At Level 4, it uses `Damage / Firerate + (Poison Damage / Tick)` because that level has no burst cooldown. The imported regular-mode table provides all six inputs for all five levels. The estimate assumes every shot poisons the same enemy, as the source states; it does not turn slowdown or defense melting into damage or account for poison refresh and target changes.

## Ace Pilot gun and bomb estimate

The current [Ace Pilot page](https://tds.wiki/w/Ace_Pilot) publishes `Gun DPS + Bomb DPS`: `Normal Damage / Firerate + Splash Damage / Bomb Cooldown`. The extractor reads these named columns from all six regular upgrade rows. Levels 0–1 have no bomb values and use only the gun rate. From Level 2, the bomb contribution is shown as a one-target-equivalent splash rate. Actual output depends on flight-path uptime, enemies caught by the blast, and projectile travel; the calculator does not multiply the splash value by an assumed target count.

## Golden Snowballer single-target estimate

The current [Golden Snowballer page](https://tds.wiki/w/Golden_Snowballer) publishes `DPS = Damage / Firerate` and states that the estimate assumes one enemy receives full damage while excluding projectile travel time. The simulator extracts all four regular levels and displays the source's maximum-hit count separately. It does not multiply that count into the displayed per-target rate; the slowdown and freeze effects are not damage inputs.

## Slime Trooper one-target estimate

The current [Slime Trooper page](https://tds.wiki/w/Slime_Trooper) publishes `DPS = Damage / Firerate` and explicitly assumes one enemy is hit and receives full damage. Its estimate excludes projectile travel time. Level 4 has splash with no listed maximum-hit cap, but that multi-enemy output is not multiplied into this one-target figure. Slowdown remains a separate support effect, not DPS.

## Pulse Trooper main-pulse estimate

The current [Pulse Trooper page](https://tds.wiki/w/Pulse_Trooper) publishes `DPS = Damage / Firerate` for its main pulse and lists `Max Hits` separately. The simulator calculates the per-target main-pulse rate and does not multiply by the maximum-hit value. Levels 4–5 also list the map-wide Sweeper lasers; those ability hits are excluded from the regular attack rate.

## Hallow Punk splash and burn estimate

The current [Hallow Punk page](https://tds.wiki/w/Hallow_Punk) publishes `Splash Damage / Firerate + Burn Damage / Tick` and states that one enemy receives full splash damage. The four-level model uses the named source columns; Levels 0–1 have no burn contribution, while Levels 2–3 add the listed burn rate. Projectile travel time and damage to additional blast targets are excluded.

`npm run test:wiki` checks all extracted tower rows against the imported revision snapshot, including source links, license policy links, level data, damage-method classification, and placement-limit shape. Negative cases remove a row, corrupt revision provenance, set an invalid cap, assign a generic formula to a special-damage tower, or remove a required Accelerator, Operator, Commando, Soldier, Golden Soldier, Freezer, Demoman, Golden Demoman, Mortar, Paintballer, Ranger, or Rocketeer cycle input; each must be rejected.

## Snowballer source formula

The current [Snowballer page](https://tds.wiki/w/Snowballer) publishes `DPS = Damage / Firerate` and states that its calculation assumes one enemy receives full damage while excluding projectile travel time. Its current statistics table lists maximum hits of 2 at Levels 0 to 2 and 3 at Level 3. The simulator calculates the same per-target-equivalent rate from the imported damage and interval, shows maximum hits separately, and excludes slowdown and freeze effects. Regression coverage checks the four source rows and rejects a missing maximum-hit input. This new visible estimate still needs a fresh built-site capture.
