# Tower simulator

Source values and derived values are stored separately. Keep unlock cost distinct from in-match placement and upgrade costs. Record units and source-specific exceptions for burst, charge, cooldown, rev-up, abilities, buffs, targeting, defense, splash, mode variants, player count, and rounding.

The current extractor processes all 83 source pages with a `TowerInfobox` and reads regular upgrade rows from the same dated revision snapshot. Each record retains its damage method, regular-mode placement limit where the source provides one, and source revision provenance. The placement-count slider respects finite caps and uses an explicit 1-10 estimate when the source gives no finite cap. Each level uses the extracted regular damage, interval, range, and detection values. Detection footnotes remain separate from the Hidden, Lead, and Flying state labels. Investment reports both per-tower and selected-count totals from the placement and upgrade costs. Missing placement costs display as unknown.

For a simple single-hit tower, the displayed steady-rate estimate is damage divided by the attack interval in seconds. It is not a guaranteed in-match damage rate and excludes buffs, target downtime, overkill, enemy defense, and range uptime. Where the source also describes firing startup, such as Minigunner rev-up, the UI says that startup is omitted. Accelerator uses the source-listed cycle formula `Overcharge / (Charge-Up + Cooldown + (Overcharge / Damage × Tick))`, with each input extracted from its imported regular-mode statistics table. The calculator displays those cycle inputs and labels its fire interval as a damage tick. The formula matches the page's published DPS values at Levels 0 and 5. Operator uses `(Damage × Burst Count) / (Burst Cooldown + (Firerate × Burst Count))` for Levels 0–4, then switches to `Damage / Firerate` for the single-fire Levels 5–6. Coordination damage buffs remain excluded. Soldier uses `(Damage × Burst Count) / (Cooldown + (Firerate × Burst Count))`, where Firerate applies between shots in one burst. Its Level 0 estimate is 2.93 and Level 4 is 54.55. Golden Soldier uses the same burst formula at Levels 0–2, then switches to `Damage / Firerate` at Levels 3–4. Its Level 0 estimate is 3.81 and Level 4 is 100. Freezer uses `(Damage × Burst Count) / (Cooldown + (Firerate × Burst Count))`; its first three levels have one shot and no between-burst cooldown, and Levels 3–4 use six and eight shots respectively. Freezer's chill and slowdown effects are excluded from the direct damage estimate. Commando uses `(Ammo × Damage) / (Ammo × Firerate + Reload Time)` for the gun magazine cycle. For example, Level 0 is `(30 × 5) / (30 × 0.225 + 2.25) = 16.67`; Level 4 is `(80 × 23) / (80 × 0.1 + 1.25) = 198.92`. Its missile ability damage is excluded even though the source lists combined gun-and-missile DPS separately. Demoman and Golden Demoman use the source-listed `Splash Damage / Firerate` as a per-target-equivalent rate. Their level rows keep splash damage and interval as explicit inputs. This is not total splash output: the simulator does not model how many enemies a blast hits, blast geometry, falloff, target overlap, or projectile travel. These formulas and inputs come from the dated imported source snapshot. Other special methods, including Biologist's mixed plant attacks and Pulse Trooper's sweeping pulse, remain unmodeled until a complete cycle formula is source-verified. `npm run test:wiki` checks all extracted tower rows against the imported revision snapshot, including source links, license policy links, level data, damage-method classification, and placement-limit shape. Negative cases remove a row, corrupt revision provenance, set an invalid cap, assign a generic formula to a special-damage tower, or remove a required Accelerator, Operator, Commando, Soldier, Golden Soldier, Freezer, or splash-damage cycle input; each must be rejected.
